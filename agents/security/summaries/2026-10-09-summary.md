## Major Developments

### 🎉 Security Fix: MCP Bridge Authentication

**Issue:** MCP HTTP bridge exposed on `0.0.0.0` with no authentication. Any process that could reach the port could call MCP tools with herdctl's privileges.

**Fix (bf4995a):**
- Random 256-bit bearer token per bridge
- Constant-time token comparison (timing attack resistant)
- Binds `127.0.0.1` by default (localhost only)
- CLI runtime uses owner-only temp file (0600) for MCP config
- Token kept out of process argv

**Impact:** HIGH - Critical unauthorized access vulnerability closed

**Test Coverage:** 192 new test lines

---

### ⚠️ OAuth Credential Logging (Finding #011)

**Issue:** OAuth token refresh functionality may leak tokens in error logs

**Specific Instances Identified:**
1. **Line 336:** `.credentials.json` written without explicit 0600 mode
2. **Line 338:** `logger.error(\`Failed to write credentials file: \${err}\`)`
3. **Line 369:** `logger.error(\`Token refresh failed: ... \${body}\`)`
4. **Line 389:** `logger.error(\`Token refresh error: \${err}\`)`

**Risk:** MEDIUM - Tokens may appear in error logs or files with wrong permissions

**Action Required:**
- Sanitize error messages (never log `err`, `body`, or auth objects)
- Add `{ mode: 0o600 }` to writeFileSync()
- Use generic error messages for auth failures
