## Security Improvement: Settings Log Redaction

**Issue:** New `settings` field can contain secrets via interpolation (e.g., `${GITHUB_TOKEN}`)
- Settings passed as `--settings <json>` argv
- Debug logs could expose `--settings` values

**Mitigation (commit 2cef420):**
```typescript
// packages/core/src/runner/runtime/cli-runtime.ts:393-399
const loggedArgs = args.map((arg, i) =>
  (args[i - 1] === "--settings" ? "<redacted>" : arg));
logger.debug(`Executing command: claude ${loggedArgs.join(" ")}`);
```

**Test Coverage:**
```typescript
it("never writes the settings JSON to the debug log", async () => {
  await captureArgs({ settings: { env: { TOKEN: "s3cret-value" } } });
  expect(logged).toContain("--settings <redacted>");
  expect(logged).not.toContain("s3cret-value");
});
```

**Impact:** Prevents secret leakage in herdctl logs (OS-level `/proc` exposure remains)

## New Feature Security Review: Settings Passthrough

### Feature Overview

Allows fleet operators to override Claude Code settings at the flag tier (highest precedence except managed policy). Settings passed to agent via `--settings <json>` (CLI) or SDK options.

### Security Strengths

1. **Two-phase implementation:**
   - Commit 1: Feature implementation
   - Commit 2: Adversarial review + log redaction

2. **Log redaction:**
   - Settings values replaced with `<redacted>` in debug logs
   - Mutation tested (removing redaction fails tests)
   - Prevents herdctl logs from leaking secrets

3. **Clear trust boundary:**
   - herdctl: Passes through verbatim (no validation)
   - Claude Code: Validates keys and values (documented)
   - Settings are flag-tier (embedder-controlled)

4. **Injection protection:**
   - JSON.stringify prevents argv injection
   - Array args (no shell execution)
   - Shallow copy prevents aliasing issues

5. **Documentation:**
   - Warns about `/proc/<pid>/cmdline` exposure
   - Documents precedence rules
   - Examples with security notes

### Security Concerns (Addressed)

| Concern | Mitigation | Status |
|---------|-----------|--------|
| Secrets in logs | Log redaction implemented | ✅ MITIGATED |
| Argv injection | JSON.stringify + array args | ✅ SAFE |
| Schema bypass | Intentional (Claude Code validates) | ✅ BY DESIGN |
| OS-level exposure | Documented as limitation | ℹ️ NOTED |

### Recommendations

1. **DOCUMENT:** Add to CODEBASE-UNDERSTANDING.md that settings validation is Claude Code's responsibility
2. **NOTE:** Settings field can carry interpolated secrets (related to Finding #011)
3. **MONITOR:** Watch for Claude Code CVEs related to settings parsing

**Overall Assessment:** ACCEPTABLE - Security-conscious design with appropriate mitigations
