#### 1. **Path Traversal Fix for Windows** (commit 31c675c - PR #210)

**Impact:** SECURITY IMPROVEMENT
**Date:** 2026-03-17
**Author:** Mariano Blua

Fixed a critical bug in `buildSafeFilePath()` that caused false positive path traversal errors on Windows. The function was using hardcoded "/" separator but Windows uses "\", causing the `startsWith()` check to always fail.

**Changes:**
- Replace hardcoded "/" with `path.sep` for cross-platform compatibility
- Handle root paths that already end with separator (avoids "//" double separator bug)
- Add comprehensive test coverage for Windows scenarios

**Security Assessment:** ✅ **Positive** - Improves path safety enforcement on Windows systems

#### 2. **File Serving Endpoint** (commit 28d4d74 - PR #394)

**Impact:** NEW ATTACK SURFACE with STRONG CONTROLS
**Date:** 2026-07-21
**Feature:** Inline image support for agent-generated content

Added `GET /files/:agentName/*` endpoint to serve files from agent working directories.

**Security Controls Implemented:**
1. **Path validation**: `isStructurallySafe()` pre-check rejects absolute paths and ".." segments
2. **Realpath resolution**: Both working directory and target path resolved via `realpath()` (defeats symlinks)
3. **Containment check**: `relative()` verifies resolved path is within working directory
4. **TOCTOU protection**: Single file descriptor opened and fstat'd (no re-touching path string)
5. **Regular file only**: Rejects directories and special files
6. **CSP headers**: `default-src 'none'; sandbox` prevents script execution
7. **MIME type control**: `X-Content-Type-Options: nosniff` prevents MIME sniffing attacks
8. **Agent name validation**: Uses existing `getAgentWorkingDirectory()` with agent name validation

**Code Review:**
```typescript
// Defense-in-depth: cheap structural check before disk I/O
if (!isStructurallySafe(relPath)) {
  return reply.status(403).send({ error: "Forbidden: path escapes working directory" });
}

// Authoritative guard: realpath both sides, defeating symlink escapes
realWorkingDir = await realpath(workingDir);
realPath = await realpath(resolved);

const rel = relative(realWorkingDir, realPath);
if (rel === ".." || rel.startsWith(`..${sep}`) || isAbsolute(rel)) {
  logger.warn("Blocked path traversal attempt", { agentName, relPath });
  return reply.status(403).send({ error: "Forbidden: path escapes working directory" });
}
```

**Security Assessment:** ✅ **Well-designed** - Multiple layers of defense, TOCTOU-safe, comprehensive logging

**Related Question:** Consider adding rate limiting to prevent directory enumeration attacks via 404 timing

#### 4. **OAuth Token Injection for Persistent Containers** (commit 18834f8 - PR #347)

**Impact:** SECURITY IMPROVEMENT (fixes credential staleness)
**Date:** 2026-07-11

Fixed OAuth token refresh for persistent containers. Previously, refreshed tokens never reached reused containers, causing auth loops.

**Changes:**
- Factor credential env vars into `extractCredentialEnv()`
- Re-inject credentials into every `docker exec` invocation
- SDK path: pass via exec `Env` option
- CLI path: pass via `-e KEY=VALUE` array args (no shell injection risk)
- Added regression test proving second exec carries NEW token

**Security Assessment:** ✅ **Positive** - Fixes credential staleness; no injection risk (array args, not shell string)

**NOTE:** This commit does **NOT** fix Finding #011 (file permissions). The `writeCredentialsFile()` function at line 336 still does not call `fs.chmodSync(credsPath, 0o600)`.
