**1. 2cef420 - feat(core): pass agent `settings` through at the flag tier**
- **Date:** 2026-10-09 (included in review window)
- **PR:** #473
- **Files:** 7 (4 production, 3 test)
- **Lines:** +142/-0
- **Security Impact:** POSITIVE

**Purpose:**
Adds flag-tier settings passthrough to Claude Code. Fleet operators can now override project settings at the highest precedence tier (except managed policy).

**Implementation:**
```typescript
// packages/core/src/config/schema.ts
settings: z.record(z.string(), z.unknown()).optional()

// packages/core/src/runner/runtime/cli-runtime.ts
args.push("--settings", JSON.stringify(options.agent.settings));

// With log redaction
const loggedArgs = args.map((arg, i) =>
  (args[i - 1] === "--settings" ? "<redacted>" : arg));
logger.debug(`Executing command: claude ${loggedArgs.join(" ")}`);
```

**Security Analysis:**

**Attack Surface:**
- NEW: `settings` field accepts arbitrary key-value pairs
- Validation delegated to Claude Code (intentional design)
- Values undergo interpolation (`${VAR}` → resolved value)

**Input Validation:**
- Schema: `z.record(z.string(), z.unknown())` (permissive by design)
- No herdctl-side sanitization
- Claude Code silently ignores invalid settings (documented)

**Trust Boundary:**
- User YAML → herdctl interpolation → CLI argv → Claude Code
- Settings are embedder-controlled (flag tier)
- Not project-controlled (lower precedence)

**Injection Risks:**
- ✅ **Argv injection:** SAFE - JSON.stringify provides escaping
- ✅ **Shell injection:** SAFE - Array args, no shell execution
- ✅ **Log injection:** MITIGATED - Redaction prevents secret leakage

**Secret Handling:**
- Settings can contain interpolated secrets (e.g., `${GITHUB_TOKEN}`)
- Log redaction prevents herdctl logs from exposing secrets
- `/proc/<pid>/cmdline` exposure documented (OS limitation)

**Test Coverage:**
- Mutation tested (removing passthrough causes failures)
- Secret redaction tested (`expect(logged).not.toContain("s3cret-value")`)
- Type contract verified

**Strengths:**
1. Two-phase implementation (feature + adversarial review)
2. Log redaction (proactive secret handling)
3. Clear trust boundary documentation
4. Comprehensive test coverage
5. Security considerations in design

**Concerns:**
1. No herdctl-side validation (ACCEPTED - by design)
2. Argv exposure via `/proc` (NOTED - OS limitation)
3. Reliance on Claude Code validation (DOCUMENTED - trust boundary)

**Risk Level:** LOW
**Recommendation:** ACCEPT - Security-conscious design with appropriate mitigations
