### Category 2: New Entry Points

#### 2.1 Workspace File Serving Route (NEW - HIGH PRIORITY REVIEW)

**File:** `packages/web/src/server/routes/files.ts` (197 lines, new file)
**Route:** `GET /files/:agentName/*`
**Purpose:** Serve files from agent working directories to enable inline image display in dashboard

**Security Posture:** ✅ **WELL-DEFENDED** with defense-in-depth

**Implemented Safeguards:**
1. **Structural safety check** (line 56-60):
   - Rejects absolute paths
   - Rejects `..` segments in both `/` and `\` separators
   - Pre-flight check before filesystem access

2. **Canonical path resolution** (line 135-145):
   - `realpath()` on working directory
   - `realpath()` on target file
   - Defeats symlink escapes

3. **Containment verification** (line 147-154):
   - `path.relative()` between real paths
   - Rejects if relative path starts with `..`
   - Rejects absolute results
   - Logs blocked traversal attempts

4. **TOCTOU race prevention** (line 156-166):
   - Opens file handle ONCE after containment check
   - All subsequent operations use the same fd
   - No window for symlink swap between check and read

5. **Type safety** (line 175-178):
   - Only serves regular files (`stats.isFile()`)
   - Rejects directories, symlinks, special files

6. **Content security headers** (line 182-191):
   - `X-Content-Type-Options: nosniff` - prevent MIME sniffing
   - `Content-Security-Policy: default-src 'none'; sandbox` - neutralize script execution
   - `Cache-Control: private, max-age=60` - conservative caching
   - Agent-produced content treated as **untrusted**

**Risk Assessment:**
- **Localhost deployment:** LOW risk (implicit trust boundary)
- **Network exposure:** MEDIUM risk (relates to Finding #012 - web API has no auth)

**Recommendations:**
1. ✅ Path traversal defenses are robust - no changes needed
2. ✅ CSP sandbox header mitigates untrusted content risk
3. ⚠️ Consider adding file size limits (DoS prevention)
4. ⚠️ Document in `ATTACK-SURFACE.md` as new entry point
5. ⚠️ Ensure localhost-only binding (relates to #012)

**Verdict:** **APPROVED** with documentation requirements

## Hot-Spot Verification Findings

### Finding #013: OAuth Credential File Permissions Not Enforced (MEDIUM)

**Status:** 🔴 **NEW** (regression check - confirming Finding #011 still present)
**Severity:** MEDIUM
**File:** `packages/core/src/runner/runtime/container-manager.ts:336`

**Description:**
`writeCredentialsFile()` uses `fs.writeFileSync()` without setting file mode to `0600`. On multi-user systems, this may expose OAuth tokens to other users.

**Evidence:**
```typescript
// Line 336 - NO file permission enforcement
fs.writeFileSync(credsPath, JSON.stringify(creds, null, 2));
```

**Recommended Fix:**
```typescript
fs.writeFileSync(credsPath, JSON.stringify(creds, null, 2), { mode: 0o600 });
```

**Related:** Finding #011 from 2026-02-20 audit
