## Change Analysis (172 commits)

### Security-Relevant Changes

**CRITICAL: MCP HTTP Bridge Authentication (bf4995a)**

**Previous State:**
- MCP bridge bound to `0.0.0.0` by default
- No authentication required
- Any process that could reach the port could call MCP tools with herdctl's privileges

**Current State:**
- Random 256-bit bearer token generated per bridge (`randomBytes(32)`)
- Constant-time token comparison (`timingSafeEqual` with SHA-256)
- Binds `127.0.0.1` by default (localhost only)
- CLI runtime writes MCP config to owner-only temp file (0600 mode)
- Token kept out of process argv

**Impact:** HIGH - Critical vulnerability closed

**Test Coverage:** 192 new test lines for mcp-http-bridge.ts

---

**HIGH: OAuth Credential Re-injection (container-manager.ts)**

**Feature:** Refreshed OAuth tokens re-injected into persistent containers

**Security Implementation:**
- Identifies credential env vars (`CREDENTIAL_ENV_KEYS`)
- Re-injects via `docker exec -e` (array args, not shell string)
- Fixes token expiry in long-running containers (#327)

**Security Concerns:**
- ⚠️ **FINDING:** logger.error() calls may leak tokens (lines 338, 369, 389)
- ⚠️ **FINDING:** `.credentials.json` written without explicit 0600 mode (line 336)
- HTTP error body from token refresh endpoint logged without sanitization

**Recommendation:** Sanitize error logging, enforce file permissions

---

**MEDIUM: Workspace File Serving Endpoint (files.ts)**

**New Route:** `GET /files/:agentName/*`

**Security Design:** EXCELLENT
- Double `realpath()` containment check (working dir + requested path)
- Rejects absolute paths and `..` segments
- TOCTOU mitigation (single fd open + fstat + stream)
- Only serves regular files
- CSP sandbox (`default-src 'none'; sandbox`)
- X-Content-Type-Options: nosniff

**Risk Assessment:** LOW - Well-designed path traversal protection

**Action:** Document in ATTACK-SURFACE.md

### Existing Findings - Updated Context

**Finding #011: OAuth Credential Management (MEDIUM)**

**Status:** Risk remains MEDIUM, specific instances identified

**New Evidence:**
- **Line 336:** `writeCredentialsFile()` does NOT set 0600 mode explicitly
- **Line 338:** `logger.error()` includes `err` that may contain token
- **Line 369:** `logger.error()` includes HTTP response `body` that may contain tokens
- **Line 389:** `logger.error()` includes `err` that may contain token

**Recommendation:**
1. Add `{ mode: 0o600 }` to `fs.writeFileSync()` at line 336
2. Sanitize all error messages:
   ```typescript
   // Bad
   logger.error(`Token refresh failed: ${body}`);

   // Good
   logger.error("Token refresh failed - check credentials");
   ```
3. Never log `err`, `body`, or `response` objects that may contain auth data

**Status:** Remains OPEN - documentation needed

**Context:** Session discovery now exposes all sessions via web API

**Risk:** Combined with Finding #011, session files may leak OAuth tokens
