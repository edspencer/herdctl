### 2. Shallow SDK Security Analysis

SDK bumps (0.3.302 and 0.3.325) introduced security-relevant changes:
- 0.3.325: "Read-only git commands now go through permission flow instead of auto-approval"
- 0.3.325: "Sandboxed Bash commands require `autoAllowBashIfSandboxed: true` to auto-approve"
- 0.3.325: "Deny rules now remove in-process SDK MCP tools from tool list"

**What was missing**:
- Does herdctl use any read-only git commands? (Could affect agent behavior)
- Does herdctl rely on auto-approval of sandboxed Bash? (Could break existing configs)
- What are "deny rules" and how do they affect herdctl's MCP usage?

**Recommendation**: When SDK updates touch security-related code paths, investigate whether herdctl's usage patterns are affected, not just "no code changes needed."

### 3. No New Questions Added

**Questions that should have been added**:
